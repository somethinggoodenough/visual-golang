# v0 实现与验收记录

日期：2026-09-22。范围依据 `docs/design.md` 的 Task 0–4；原始文档保留在仓库根目录。

## 已实现

| 能力 | 实现方式 |
| --- | --- |
| Go → IR | `go/parser`、`go/ast`、`go/types`；按实际 Object 绑定识别内建函数与 `fmt.Println` |
| IR 合同 | 版本 1.0，严格联合 JSON 编解码；类型、唯一 ID、父子关系、词法可见性、捕获与容量检查 |
| IR → Go | 递归构建 AST，匿名函数在原词法位置内联；格式化后重新解析、检查生成绑定并重建映射 |
| 往返一致性 | Normalize 对函数、块和符号重新编号，保留名称、类型、声明、绑定、容量、值、顺序及嵌套 |
| 编译 | 本机 `go build`；独立临时目录、超时、输出限制、清理产物；不执行生成的二进制 |
| 图形编辑 | React Flow 执行区域、独立 Channel 资源、顺序/spawn/引用边；工具箱点击或拖入、端口绑定、属性修改、排序、删除 |
| 编辑状态 | source/graph 单侧草稿、明确应用、错误保留最近有效模型、放弃确认、语义与布局撤销/重做、请求过期保护 |
| 源码定位 | 节点与源码双向选择；UTF-8 byte / UTF-16 转换；诊断定位到所属操作 |
| 持久化 | `.go` 与 `.goviz.json` 导入导出；原始源码副本、ID、修订、节点位置、折叠、视口保存 |
| 项目验证 | 校验版本、IR、hash、布局引用；重导 source 比较 Normalize；重建映射，不信任文件中的旧 sourceMap |
| 启动交付 | 开发模式一条命令启动前后端；生产构建由 Go 服务提供静态资源；依赖提交确切版本与 lockfile |

Channel 资源视图使用其 SymbolId，创建操作继续使用自己的 StatementId，因此同一声明有两个不同视图且不会与合法自定义 ID 冲突。布局字典支持 `__proto__` 等普通字符串 ID。

## 实际验证环境

- macOS / arm64；Go `go1.27.1 darwin/arm64`。
- Node.js `v22.22.3`，npm `10.9.8`。
- React `19.3.0`，React Flow `12.11.6`，Vite `8.3.0`，TypeScript `7.0.2`。
- Playwright `1.63.0`，使用本机 Google Chrome，无头浏览器。
- 不依赖 mock API 完成成功路径；转换、项目验证和正常编译均调用真实 Go 服务。

## 自动化覆盖

最终执行结果：

| 命令 | 实际结果 |
| --- | --- |
| `npm test` | 25 个 Go 测试函数及各自子用例通过；TypeScript 检查、Vite 构建通过 |
| `go test -race ./...` | 全部通过，无竞态报告 |
| `npm run test:e2e` | 19/19 通过（8 个浏览器流程、11 个模型/状态测试），耗时 18.7 秒 |
| `npm run build` | 前端与 Go 服务构建成功 |
| `npm run test:smoke` | 生产服务 HTML、构建 JS 资源及实际工具链 health 均通过 |

最终浏览器回归没有出现早期验收中的 ResizeObserver 循环或节点未初始化警告。测试启动器仍可能打印环境中 `NO_COLOR` 与 `FORCE_COLOR` 同时存在的提示，不影响程序或检查结果。

后端测试覆盖：示例 fixture、规范 JSON fixture、容量 0/1、遮蔽、嵌套捕获、五种接收绑定、完整往返、实际 Go 编译、未使用变量、非法类型与 IR、严格 JSON、int 范围、UTF-8 位置、项目损坏与源模型不一致、映射重建、请求边界、版本与请求 ID 回显、编译超时和工具链不可用。

`go test -race ./...` 用于检查并发转换和共享标准库导入缓存；导入器另运行了 5 秒模糊测试，完成 167,193 次执行，未出现 panic、可编辑模型无法生成或 Normalize 往返变化。

浏览器及模型测试位于 `frontend/e2e/`：

1. 导入示例，42 改 100，应用，真实编译，导出 Go 再导入，保存并恢复项目。
2. 从空模型使用工具箱和资源端口构建示例；修改容量；非法排序被拒绝且可放弃。
3. 纯布局拖动不变源码与语义修订；错误代码保留最近有效图形；中文和 emoji 源码位置双向匹配。
4. 请求返回前继续编辑，旧响应不覆盖新的草稿。
5. 后端不可达、编译失败、超时、工具链缺失正确显示错误状态。
6. 表达式诊断可定位发送属性；小窗口首次导入可见 Channel 资源。
7. 模型命令构图、作用域/遮蔽、引用删除保护、接收变量身份、大整数精度、布局与语义撤销重做、草稿互斥、任意 ID 的布局恢复。

编译错误类别的前端显示用定向失败响应测试；后端分别测试了真实缺失路径、超时进程及失败输出，正常成功路径使用真实 Go 编译器。没有运行任何用户 Go 程序。

浏览器截图用于检查 1512×982 与 1366×768 桌面布局。截图、失败 trace 与运行报告生成于 `frontend/test-results/`，不作为业务数据提交。

## 当前边界

- v1 模拟、v2 扩展语法、v3 trace/线程/多进程视图尚未实现，也没有占位运行按钮。
- 支持范围严格限定为设计文档中的单文件 v0 子集；不联网解析外部 Go 依赖。
- 图形生成会规范化代码；注释和原排版可从保存的原始源码副本取回。
- 不支持将既有操作通过坐标拖动移入另一个函数作用域；可在目标函数重新添加操作。
- 界面针对桌面使用，最小工作区宽度为 1000px；小于此尺寸可横向滚动。未对移动触屏交互、Safari、Firefox 或 Windows 作实际验收。
- 编译成功不能证明程序不会阻塞、死锁或发生运行时错误。
